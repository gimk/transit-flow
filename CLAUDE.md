# Transit Flow

2D top-down street design game in **Rust + Bevy**. The player is an urban designer in Paris: each level is one real intersection with fixed buildings and kerb-to-kerb width; the player shares the space between cars, cyclists and pedestrians (strip use, rules, signals, crossings, obstacles, green areas), then starts the run and only watches. Annoyance, conflicts and injuries cost points; a death is a game over; free space, rest and green areas give a bonus. **Realism first, fun later**: it is a simulation before it is a game. Each star of a level is a load stage (more cars, pedestrians, cyclists on the same design, until it breaks).

- **Roadmap, design and phase status: [docs/URBANISM_PIVOT_PLAN.md](docs/URBANISM_PIVOT_PLAN.md)** (approved 2026-11-16). Read it before starting a phase, and update its **Status** line and phase details when a phase is done or the design changes.
- **The pivot is in progress.** Until Phase 5 of the pivot plan, the tree holds two games: the old city builder (everything described below this section, except where a rule says "new code") and the new street game (`tf_sim::street` and its views). The old systems are **frozen** during Phases 1 to 4: do not change or delete them; their tests (goldens included) must stay green. New code goes in new modules and depends only on the modules the plan marks KEEP or ADAPT (section 2.2), never on DROP modules. Phase 5 deletes the old game.
- The city builder: the old roadmap [docs/IMPLEMENTATION_PLAN.md](docs/IMPLEMENTATION_PLAN.md) (replaced, kept as the record) and [game_design_architecture_concept.md](game_design_architecture_concept.md). Its last commit is the git tag `city-builder-final` (local only).
- History: the game was written in Godot 4.7 / GDScript and ported to Rust + Bevy ([docs/BEVY_MIGRATION_PLAN.md](docs/BEVY_MIGRATION_PLAN.md), done; decisions and deviations in [docs/migration/NOTES.md](docs/migration/NOTES.md), the historical log). The Godot project is gone from the tree; its last commit is the git tag `godot-final` (local only).

## Commands

Cargo lives in `~/.cargo/bin`; `~/.zshrc` loads it. In a shell that doesn't, `source "$HOME/.cargo/env"` first.

- `cargo play`: runs the game (alias in `.cargo/config.toml` for `cargo run -p tf_game --features dev`, which links Bevy dynamically for fast rebuilds). Arguments go after `--`. Release: `cargo run -p tf_game --release`.
- `scripts/check.sh`: `cargo fmt --check` + `cargo clippy --workspace --all-targets -- -D warnings` + `cargo test --workspace`. **Run it before every commit**; it must exit 0. Run `cargo fmt` first if it complains about formatting.
- **Screenshot mode (visual checks):** `cargo play -- (--scenario <empty|bottleneck|bottleneck-bus|town> | --level <id>) --frames N --screenshot out.png [--hour H] [--zoom Z] [--overlay heatmap|lanes]` runs N frames at a fixed 1/60 s step, writes a 1280x720 PNG of the window and exits 0 (bad args: usage, exit 2). `--hour` runs the sim ahead to that time of day first; `--zoom` snaps to a `ZOOM_LEVELS` step (default: framed like the F key); `--overlay` sends `DebugOverlayToggleRequested`. `--level carrefour-ecole` shows a street-game level, framed on its bounds (not with `--hour`). A real window opens briefly (macOS can't render without one). Put PNGs in a scratch dir, never commit them; look at them with the Read tool. Code: `crates/tf_game/src/capture.rs`.
- **Screenshots come out black if the display is asleep** (the GPU doesn't present): run `(caffeinate -u -t 120 &); sleep 1` first.
- **Frame-time benchmark:** `target/release/transit-flow --bench-frames 600 [--bench-vehicles 2000] [--bench-overlay heatmap|lanes]` (build with `cargo build --release -p tf_game`; the first release build takes ~20 min). Loads the Town, sets stress traffic, waits until the vehicles are up, then prints the frame interval (avg / p99 / worst), the main-thread update time, the sim tick cost and the snapshot capture cost over N frames, and exits. Threaded runner, vsync off, but macOS still presents on the display's 60 Hz clock, so a frame interval of 16.7 ms means "holds 60 FPS", not the real cost: read the main-thread figure. Code: `crates/tf_game/src/bench.rs`.
- **Sim benchmarks** (headless, no Bevy): `cargo run -p tf_sim --release --bin traffic_benchmark` (per-tick cost at 500 / 1k / 2k / 5k vehicles), `--bin town_benchmark` (the Town for a day, then with 2 000 stress vehicles), `--bin run_baseline` (the behaviour metrics of `migration/baseline.md` on the Rust sim next to Godot's, with a verdict; exits 1 if one is out of its band). Reference: 2 000 vehicles cost 1.65 ms per tick (26.5 ms in GDScript), the Town runs 14x faster.
- **Street run (headless):** `cargo run -p tf_sim --release --bin run_level -- <level-id> [--design <file.json>] [--seed <n>] [--population careful|mixed|careless] [--demand-scale <x>] [--events]`. It prints the summary, the event log hash and the speed against real time; `--events` prints the event log first.

## Disk hygiene

The developer works on a MacBook Air with little storage. `target/` (git-ignored) grows without bound: the debug build once reached 28 GB (`deps/` 23 GB, `incremental/` 5 GB) against ~15 MB of source. Everything in it is regenerable, so keep it small.

- **When:** at the end of a work session or a long task, and whenever `du -sh target` shows more than ~8 GB. Check with `du -sh target target/*`.
- **Routine clean-up:** `cargo clean --profile dev` (drops the debug build; the next `cargo play` recompiles once, slowly). Keep `target/release` (~2 GB) unless space is critical: its first build takes ~20 min. `cargo clean` removes everything, release included.
- **Lighter option:** `rm -rf target/debug/incremental` (~5 GB) costs little to rebuild.
- **Scratch files:** screenshots, benchmark output and other temporary files go in the scratchpad or a temp dir, never in the repo; delete them when done. `find . -name .DS_Store -not -path './target/*' -delete` removes macOS junk (already git-ignored).
- **Before deleting:** it is safe only for build output. Never delete `migration/` (golden test data), saves under `~/Library/Application Support/transit-flow/`, or anything untracked you did not create. Tell the user what was freed.

## Keys

`tf_game::input::KeyBindings` maps actions to physical keys (`KeyCode`), so WASD = ZQSD on AZERTY. WASD / arrows pan, wheel zooms toward the cursor (9 steps), middle-drag and trackpad pan, pinch zooms; space pause, 1-3 speed; tools R B H C I X L U T V and Esc; F2 lateness, F3 lanes, F4 heatmap (overlay toggle messages), F5 save, F9 load (`~/Library/Application Support/transit-flow/quicksave.json`, `TRANSIT_FLOW_DATA_DIR` overrides), F6 stress traffic (cycles 0-2000 vehicles), F7 Bottleneck, F8 Town, F11 fullscreen, F10 (or P) rush hour now, F12 (or N) new empty map, 0 Bottleneck with bus lanes. Tools: R road (again: next road type; V: curved roads), B bulldoze, H/C/I zone residential/commercial/industrial, X dezone, L junction control (none / lights / protected lefts), U bus lines (click stops in order, the first again to open the line; U again: curbside stops / bus bays), T route inspector. Systems read `ActionInput` and the `Pointer` resource (world / snapped position, buttons), never raw keys or the window. Camera state is in sim coordinates (y down); the Bevy world is y up (`camera::sim_to_bevy` negates y).

## Architecture rules

- **`tf_sim` is pure and Bevy-free.** Plain structs, no ECS, no rendering, no threads, no wall-clock time, no `unsafe`. Dependencies: `glam`, `serde` / `serde_json`, `ron`, `indexmap`, `smallvec` (tests: `approx`); every version is pinned in the root `Cargo.toml` (`glam` must stay the version Bevy uses). It must be steppable headless from tests. Bevy is used only in `tf_game`; don't upgrade it casually (exact pin).
- **Fixed tick.** The sim advances only via `Simulation::step()` (20 Hz, `Simulation::TICK_DT`), driven by the runner in `tf_game`. Never use frame `delta` inside the sim. Pausing = speed 0 in the runner.
- **Events: the `Outbox`.** A system never holds another system. It pushes a `SimEvent` into the `Outbox` it was given, and `Simulation::call(|sim, out| ...)` delivers the outbox to the listeners as soon as the call returns, in the order `Simulation::new` wires them (roads -> router -> lots -> zones -> externals -> signals -> vehicles -> pedestrians -> transit -> citizens -> freight -> stress -> congestion -> flow). Each listener runs through `call` too, so its own events are delivered first (depth first). The order is behaviour: listeners are called in the order Godot connected them (table in NOTES.md, "Event dispatch"). The views get every event last through `Simulation::take_view_events`. A system method takes the other systems it needs as parameters (a context struct), never stores references. `step()` runs zones, citizens, freight and stress traffic (departures), traffic lights, pedestrians, transit, vehicles (movement, arrivals), then the congestion monitor (every 5 s).
- **Threaded runner (`tf_game::runner`).** `SimHandle` holds the sim as `Option<Box<Simulation>>` and moves it by value to a worker thread, which steps a batch (at most 4 ticks), `LEAD_TICKS` (2) ahead of the screen, captures a `ViewSnapshot` after each tick and sends it all back. No locks. Per-frame view code reads `view_from` / `view_to` / `view_alpha` (interpolate between the two), never the sim. Tools, saves and anything else that must touch the sim call `SimHandle::get_mut()`, which waits for the worker (fine on a click, a hitch if done every frame). Road geometry for views is the `Arc<RoadsView>` published after every edit (`version` tells views to rebuild), so views never wait. Edits made through `get_mut` reach the views as messages at the next `advance`. `threaded: false` runs batches inline (tests, screenshot mode).
- **Messages.** Bevy `Message`s (not observer `Event`s) in `tf_game::events` mirror the sim's events for the views and UI (`RoadNetworkChanged`, `LotsChanged`, `ToolChanged`, `NotificationPosted`, ...).
- **Views only read** snapshots, `RoadsView` and messages. They draw **simple flat shapes** with Bevy's 2D meshes and one `ColorMaterial` (`draw::ShapeBuilder`: vertex colours, no shaders, no textures); depths are the constants in `views::z`. Static shapes (roads, lots, zones) are rebuilt only for what a change message names; moving things (vehicles, parked cars, pedestrians) are one batched mesh each, rewritten in place every frame. Debug overlays use gizmos or a mesh. The art direction is to be redone later.
- **Tools** live in `tf_game::tools`: the `ToolManager` resource holds every `BuildTool` (`activate`, `update`, `cancel`, variants, `preview`). A tool reads the `Pointer` and `ActionInput`, never the window, and edits the sim only through command methods on sim systems, via `handle.get_mut().call(|sim, out| sim.roads.add_road(.., out))`. Tools with variants (road types, bus stop kinds) implement `variants` / `set_variant`.
- **Ids and order.** Every id-keyed collection in the sim is an `IndexMap<i32, X>` (or a newtype id like `LaneId`, `VehicleId`). **Removals use `shift_remove`, never `swap_remove`**; iteration is in insertion order and a lot of behaviour depends on it. No `HashMap` iteration in sim logic. References between objects are ids, never `Rc`/`RefCell`.
- **Determinism.** The same inputs give the same run. `rng::SimRng` is a bit-exact copy of Godot's `RandomNumberGenerator` (PCG32); systems keep their original seed constants, and the order of draws is part of the behaviour. `f64` for GDScript-style floats (speeds, times, distances held in vehicles), `f32` / `Vec2` for geometry (polylines, `Curve2D`); mixed expressions follow the same split as before (NOTES.md, "Number types"). **New code** (`street/`): a run is a pure function of `level + design + seed`. Each agent gets its own `SimRng` stream seeded from `(run seed, agent id)`, so one more agent does not shift the draws of the others; agents update in id order from the state of the previous tick; nothing from the frame (real delta, batch size) enters the sim.
- **Units.** The old game works in world pixels with compressed time and distance. **New code works in metres and seconds with real speeds** (injury depends on real speed); a level is about 150 m × 150 m. Never mix the two: new code does not reuse pixel constants of the old systems.
- **Everything is a lane**: roads and intersection turns are `Lane`s holding a `Curve2D` (a baked polyline); never move vehicles tile-by-tile. The grid is a UI aid only (`Grid` snapping in tools); the sim works in world pixels.
- **Roads:** edits go through `RoadNetwork` commands (`add_road` / `add_road_pieces`, `add_curved_road` / `add_path_pieces`, `remove_segment`, `set_segment_type`, `set_node_control`), which report `SimEvent::RoadsChanged(ChangeSet)` (the node and segment ids touched). Adding a road splits existing segments where it meets them, so segment ids are not stable across edits (ids in a change may refer to removed things). Lanes are derived data: never saved, rebuilt from centerlines. Road lanes keep their ids until the segment is removed or retyped; connector lanes (junction turns, `segment_id == -1`) get new ids whenever their node changes; removed lane ids are retired, not reused. Road types are data: `crates/tf_sim/data/road_types/*.ron`, embedded with `include_str!`; the road tool cycles through them all (R again).
- **Routing:** `router.find_route(from_lane, from_distance, to_lane, to_distance)` returns a `Route` (lane ids + distances) or `None`; A* is our own (`routing/astar.rs`, ties as Godot's). Trip endpoints are positions along road lanes, never nodes. A lot offers both lanes of its street (`LotSystem::access_points`); trips between lots use `find_best_route(starts, ends)`. Congestion costs come from `CongestionMonitor` every 5 s and are shared with `router.graph.congestion`.
- **Junctions:** control lives on `RoadNode.control` (none, lights, lights with protected lefts); light phases belong to connectors (`Lane.signal_phase`), vehicle-actuated by `Simulation.signals` (`TrafficLights`, state not saved). Without lights, `RoadType.priority` decides first who gives way. Conflict zones (`Lane.conflicting_lane_ids` / `conflict_zones`) plus gap acceptance decide entry; priority straight > right > left, then to the right. **Safety invariant** (checked every tick by `debug::checks`, used by the stress and Town tests): never two vehicles in the zone two conflicting connectors share, no overlaps, no pedestrian on a crosswalk while a car is on a turn over it.
- **Vehicles:** only `VehicleSystem` creates, moves or removes them. Per-lane queues live in `VehicleSystem` (`queue(lane_id)`, front-most first; only non-empty lanes are kept, in the order they became occupied), so the road network stays read-only during a tick. `depart` (the vehicle waits in its driveway until it can pull out) vs `spawn` (on the road at once: debug traffic, tests). It reports arrivals and failures (incl. patience give-ups) as events. Lane changes (`change_lanes`: gaps, zipper merging, a give-up after 2 s at the end of the lane), `Lane::is_beside`, bus lanes (`Lane.bus_only`: cars route on a graph without them) and passing a bus dwelling in the lane are all in `traffic/vehicle_system`.
- **City:** lots are buildings (`Lot.plot`: the cell less what the roads take; a road that leaves less than `MIN_PLOT` removes the lot and the zone waits); `ZoneSystem` creates them on zoned cells (`LotSystem::add_lot` is for scenarios and tests). Citizens and freight decide trips and start them with `depart`. A citizen's trip is a list of legs (walk / car / bus; `plan_trip`: generalized-cost mode choice, the car only from where it's parked, `Parking` spaces per lot). Flow scores it door to door from `trip_ended`, so citizens' cars and buses are flagged `scored_by_owner` and not scored on their own. New maps get a highway via `debug::scenarios::add_highway`; `Simulation::new()` alone gives an empty map (used by tests).
- **Pedestrians:** `WalkNetwork` (sidewalks, corners, crosswalks at junctions of 3+ roads, derived from the roads), `PedestrianSystem` (door-to-door walks, waiting at the curb), shared `Crosswalks` state (key `(node id, crossed segment id)`): cars give way to people on or waiting at a crosswalk their turn crosses, people wait while a car is on such a turn, at lights they walk with the parallel through phase; without lights a driver who has waited `CROSSWALK_PATIENCE` goes once it's empty. Walking is a sixth of car speed.
- **Buses:** `TransitSystem` owns stops (`BusStop`: position + direction, re-found on the lanes after road edits), lines (`BusLine`, loops, fixed stop-to-stop `routes`) and the buses. Buses are ordinary vehicles with `in_service`: they `dwell` at each stop until TransitSystem sends them on (`set_route`). Riders wait at stops and come back through `rider_arrived` / `rider_stranded`. At a bay a bus leaves its lane's queue (`pull_into_bay`) and pulls back in at a gap. Every stop has a mid-block crosswalk (`Crosswalks::mid_block`).
- **Saves:** `Simulation::to_dict()` / `from_dict()`, JSON (sorted keys, tab indent), `Simulation::SAVE_VERSION` (1). Bump it when the format changes incompatibly. Roads, lots, zones, external connections, bus stops and lines are saved; citizens, vehicles (buses too), light states and Flow history are not (people restart at home on load). Typed structs everywhere; `serde_json::Value` only at the save boundary. Saves made by the Godot build still load.
- **Golden and trace tests pin Godot's behaviour.** `migration/golden/*.json` (road, lane, route, plot, walk, transit dumps and the tick-by-tick traffic, bus, citizen, Town and playtest traces) were produced by Godot scripts that now exist only in the `godot-final` tag (`migration/README.md` lists them). A failing golden or trace test means the behaviour changed: fix the code, unless the change is deliberate; then update the golden *knowingly* and say so in the commit. Goldens can only be regenerated by checking out `godot-final` and running the Godot scripts (Godot 4.7.2); otherwise edit expectations by hand only with a good reason. Never weaken an assertion to make a test pass. **Pivot policy (plan section 2.3):** the goldens pin the old game only. They are retired **with the code they pin, in the same commit, and the commit says so** (Phase 5); they are not weakened and not re-pinned before that. The new game's safety net is replay hashes made by our own sim (`level + design + seed` → hash of the event log, stored in the repo); a changed hash means behaviour changed, and the commit must say it is deliberate.
- **Street model (new code, `tf_sim::street`).** A level is a RON file in `crates/tf_sim/data/levels/` (registered in `street::level::LEVELS`); the player's design is a list of `DesignCommand`s (JSON). `Street::from_level_and_design` replays it; `Street::apply` is the only way to edit and rebuilds the lanes of the touched segments and the movements of their junctions. Lanes and movements are derived, get new ids when rebuilt, and are never saved. Views draw it from `tf_game::level::LoadedLevel` at `PX_PER_M` pixels per metre.
- **Street run (new code, `tf_sim::street::run`).** A run is `StreetRun::new(level, design, options)`, then `step()` at 20 Hz. Agents decide from past snapshots, in id order, each with its own `SimRng`. The event log is the result: score, report and replay hashes are read from it. Replay hashes are in `crates/tf_sim/tests/street_run.rs`. Vehicles are in `StreetRun::agents`, pedestrians in `StreetRun::walkers` (ids from `WALKER_ID_BASE`, so a walker never shifts the id or the stream of a vehicle); all the draws of a walker are made at spawn. Crossings are data (`Street::crossings`, `DesignCommand::AddCrossing` / `RemoveCrossing`). New street code uses no `sin` / `cos` / `exp` / `powf`, so that every platform gives the same bits.
- Only add a feature or retune a constant on purpose (the sim is balanced by playtest); behaviour changes are the user's call.

## Code style

- `cargo fmt` (rustfmt defaults, `.editorconfig` for the rest) and `clippy -D warnings`; no `unsafe`; `unwrap()` only where a broken invariant should crash (prefer `expect("why")`).
- `//!` under a module and `///` on public items explain the role and the *why* (the rule, the Godot behaviour kept, the reason for an order), not the *what*.
- Constants `UPPER_SNAKE`; events and messages named in the past tense (`RoadNetworkChanged`).
- New sim logic gets tests: next to the code for small units, in `crates/tf_sim/tests/` (or `crates/tf_game/tests/app/` for tools, views and keys: one module per file, added in `main.rs`; run one with `cargo test -p tf_game --test app tools::`) for behaviour. Scenarios and checks shared between tests are in `tests/common/` (tf_sim) and `tests/app/common/` (tf_game) and `debug::checks`.
- Match the existing names: the sim's classes keep the names they had in GDScript (`RoadNetwork`, `VehicleSystem`, ...), which keeps `docs/migration/NOTES.md` and the old plan readable.
