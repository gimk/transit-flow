# Transit Flow

2D top-down traffic & transit city builder in **Godot 4.7 / GDScript**. The player zones R/C/I and designs roads and transit; the city builds itself; the score is "Flow Efficiency %".

- Game design: [game_design_godot_architecture_concept.md](game_design_godot_architecture_concept.md)
- Architecture, roadmap, phase status: [docs/IMPLEMENTATION_PLAN.md](docs/IMPLEMENTATION_PLAN.md) — read it before starting a phase, and update its **Status** line and phase details when a phase is done or the design changes.

## Architecture rules (see the plan for details)

- **`sim/` is pure logic**: `RefCounted` classes, no `Node`, no autoload access, no rendering. Must be steppable headless from tests.
- **`view/` only reads sim state**; **`tools/`** mutate the sim only through command methods on sim systems (e.g. `RoadNetwork.add_road`).
- **Fixed tick**: the sim advances only via `Simulation.step()` (20 Hz, `Simulation.TICK_DT`), driven by the `Game` autoload. Never use frame `delta` inside the sim.
- **Threaded sim** (outside headless runs): `Game` steps the sim on a worker thread, a couple of ticks ahead of the screen, and captures a `ViewSnapshot` after each tick. Per-frame view code (anything in `_process` or redrawn every frame) reads `Game.view_from` / `view_to` / `view_alpha`, never the live sim. `Game.simulation` waits for the worker before returning it (fine for tools, events, saves; a hitch if used every frame). `Game.roads` reads road geometry without waiting (only the main thread changes roads). Sim signals the views need are relayed to `Events` on the main thread by `Game`; never connect a view directly to a sim signal. Tests run headless, where the sim steps inline.
- Pausing = `Game.set_speed(0)`, not `get_tree().paused`.
- Cross-system notifications go through the `Events` autoload signal bus.
- **Everything is a lane**: roads and intersection turns are `Lane`s holding a `Curve2D`; never move vehicles tile-by-tile, never use `TileMapLayer` for roads (zones only).
- Grid snapping is a UI aid only (`Grid.snap_to_point`); the sim works in world pixels.
- Road edits go through `RoadNetwork` commands (`add_road` / `add_road_pieces`, `add_curved_road` / `add_path_pieces`, `remove_segment`; curved roads are dense polylines, lanes on them slow down in tight bends), which emit `changed(node_ids, segment_ids)`. Adding a road splits existing segments where it meets them, so segment ids are not stable across edits; views update incrementally from those ids (ids may refer to removed things). Lanes are derived data: never saved, rebuilt from centerlines. Road lanes keep their ids until the segment is removed or retyped (`set_segment_type`, or dragging another road type over it); connector lanes (junction turns, `segment_id == -1`) are regenerated with new ids whenever their node changes.
- Routing: `Simulation.router.find_route(from_lane, from_distance, to_lane, to_distance)` returns a `Route` (lane ids + start/end distances) or null. Trip endpoints are positions along road lanes, never nodes. A lot offers both lanes of its street (`LotSystem.get_access_points`); trips between lots use `router.find_best_route(starts, ends)` to pick the quickest pair.
- Build tools extend `BuildTool`, live under the `ToolManager` node (node name = tool id), and read the pointer with `get_pointer_position()` / `get_snapped_pointer_position()`, never `get_global_mouse_position()` (which ignores synthetic test input).
- Saves: `Simulation.to_dict()` / `from_dict()`. Bump `Simulation.SAVE_VERSION` when the format changes incompatibly. Roads, lots, zones, external connections, bus stops and lines are saved; citizens, vehicles (buses too), light states and Flow history are not (people restart at home on load).
- **`dispose()` discarded simulations and road networks** (`Simulation.dispose()`, `RoadNetwork.dispose()`): lanes link to each other (`Lane.outgoing_lanes`) and to the vehicles in their queues, so without it they are never freed. `Game` does it when replacing or exiting; tests do it in `after_each`. A "resources still in use at exit" error means something wasn't disposed.
- Vehicles: only `VehicleSystem` creates, moves or removes them. Per-lane queues live on `Lane.queue` (front-most first). Junction entry is granted per connector using conflict zones (`Lane.conflicting_lane_ids` / `Lane.conflict_zones`) and timing, plus gap acceptance against approaching traffic with priority (straight > right > left, then priority to the right; `_gap_accepted`, `_must_yield`); drivers slow to look at junctions without lights. See the `VehicleSystem` class doc. Safety invariant (checked by the stress tests): never two vehicles inside the zone two conflicting connectors share. Lane changes: a route may step sideways to the lane next door (`Lane.is_beside`); `VehicleSystem._change_lanes` moves vehicles across in gaps, with zipper merging, swaps and a give-up after 2 s at the end of the lane. Hot paths hold `Lane` objects (`Lane.outgoing_lanes`, `Vehicle.next_lanes`) rather than ids.
- City: lots are buildings; `ZoneSystem` creates them on zoned cells (hand-placed lots via `LotSystem.add_lot` are for scenarios/tests). Citizens and freight decide trips and start them with `VehicleSystem.depart` (the vehicle waits in its driveway until it can pull out; `spawn` puts one on the road at once, for debug traffic and tests); `VehicleSystem` drives them and reports `vehicle_arrived` / `vehicle_failed` (incl. patience give-ups), which `FlowMetric` scores. A citizen's trip is a list of legs (walk / car, `CitizenSystem.plan_trip`: generalized-cost mode choice, the car only from where it's parked, `Parking` spaces per lot); Flow scores it door to door from `CitizenSystem.trip_ended`, so citizens' cars are flagged `Vehicle.scored_by_owner` and not scored on their own. New maps get a highway via `Scenarios.add_highway`; `Game.new_simulation()` alone gives an empty map (used by tests).
- Pedestrians (`sim/walking/`): `WalkNetwork` (sidewalks, corners, crosswalks at junctions of 3+ roads, derived from the roads), `PedestrianSystem` (door-to-door walks, waiting at the curb), and the shared `Crosswalks` state (key `Vector2i(node id, crossed segment id)`): cars give way to people on or waiting at a crosswalk their turn passes over, people wait while a car is on such a turn, and at lights walk with the parallel through phase (starting only in its first `TrafficLights.WALK_INTERVAL`); without lights a driver who has waited `VehicleSystem.CROSSWALK_PATIENCE` goes once the crosswalk is empty. Walking is a sixth of car speed.
- Buses (`sim/transit/`): `TransitSystem` owns stops (`BusStop`, at the curb, kept as position + direction and re-found on the lanes after road edits), lines (`BusLine`, loops) and the buses running them. Buses are ordinary vehicles with `Vehicle.in_service`: VehicleSystem keeps them on the road `dwelling` at each stop until TransitSystem sends them on with `VehicleSystem.set_route`; they're flagged `scored_by_owner` (Flow scores riders, not buses). Riders wait at stops (`wait_for_bus`) and come back through `rider_arrived` (with the bus door they step off at) / `rider_stranded`; `plan_ride` is the bus option in `CitizenSystem.plan_trip`. Buses drive their line's fixed stop-to-stop routes (`BusLine.routes`). At a bus bay (`BusStop.bay`) a dwelling bus leaves its lane's queue (`VehicleSystem.pull_into_bay`) and pulls back in at a gap. Bus lanes (`RoadType.bus_lanes`, `Lane.bus_only`): cars route on a graph without them (only crossing to the curb, or turning right out of them), buses pass `bus = true` to the Router. Every stop has a mid-block crosswalk (`Crosswalks.mid_block`, keys `Vector2i(MID_BLOCK_BASE - stop id, road id)`). Drivers behind a bus dwelling in their lane pull out round it (`VehicleSystem._pass_stopped_buses`).
- Lots stand on a plot (`Lot.plot`): their cell less what the roads around it take (half width + sidewalk, `LotSystem.compute_plot`); a road that leaves less than `MIN_PLOT` removes the lot and the zone waits. `LotRenderer` draws the building at the back and a marked parking strip at the front with the parked cars (`ViewSnapshot.parked`). Vehicles are drawn by `view/vehicle.gdshader` on one MultiMesh (shape per kind, lamps from `ViewSnapshot.indicators` and speed changes, headlights at night); colours: cars shades of green, trucks brown (bus-sized), buses their line's colour (blue, pink, purple, yellow). Buildings: `BuildingPainter`, a style per zone seeded by the lot's cell. Trees on unzoned land: `NatureRenderer`, view only, derived from roads, zones and lots. Night lights (lamps, lit windows): `NightLights` (Node2D in World). The light vehicles throw on the road (beams, brake and indicator glows) and their lit lamps are `vehicle_light.gdshader`, on `VehicleLights`, a sibling drawn just before `VehicleRenderer` (behind all bodies, so it never lights another car). Lights divide by `DayNight.applied_tint` so the night tint doesn't darken them.
- **Dot display (Phase D, the game's look):** `DotDisplay` (CanvasLayer 5, under the HUD at layer 10) renders the world as an amber LED dot matrix. Every renderer under World draws into one display layer (`DotDisplay.ROUTES`: map, actors, light, information), each a `SubViewport` sharing the World2D and filtering by `visibility_layer` / `canvas_cull_mask`; `dot_display.gdshader` composites them into dots on a world-space grid (cell = power of two in world px, picked by zoom), with priorities (solid information > light > actors > square marks > ring marks > map: two extra information layers whose style is the dot shape; deeper `ROUTES` paths such as `TransitRenderer/Lines` override their parent) and the lighting (the world is drawn unlit while it's on; `DayNight` leaves it untinted). **A new renderer under World must be added to `DotDisplay.ROUTES`** (`test_every_world_renderer_has_a_display_layer`). `MapCamera` zooms in steps (`ZOOM_LEVELS`) that keep dots 3-4 screen px apart; the zoom also picks a level of detail (`DotDisplay.current_band`: Detail, Street, District, City; `Events.dot_band_changed`) that renderers draw per band (design in the plan, Phase D-LOD). Problems are drawn by `AlertRenderer` (information layer, blinking by dimming itself). **The composite reads at most six layer textures**: a seventh was not reliably bound (D3D12). The debug toggle "Dot display" switches back to the old look (until the end of Phase D).
- Junction control lives on `RoadNode.control` (set via `RoadNetwork.set_node_control`): none, lights, or lights with protected left turns; light phases belong to connectors (`Lane.signal_phase`) and are vehicle-actuated by `Simulation.signals` (`TrafficLights`, state not saved). Without lights, `RoadType.priority` decides first who gives way. Congestion costs come from `CongestionMonitor` every 5 s and are shared with `router.graph.congestion`.
- **Never connect a lambda that captures `self` to a signal of another sim object** (e.g. `roads.changed.connect(func(): _dirty = true)`): the lambda keeps `self` alive through the signal, forming a reference cycle that leaks the whole `Simulation` ("resources still in use at exit"). Connect a bound method instead.
- Sim systems are wired in `Simulation._init` in dependency order (roads → router → lots → zones → externals → signals → vehicles → pedestrians → transit → citizens → freight → stress → congestion → flow); `step()` runs zones (development), citizens, freight and stress traffic (departures), traffic lights, pedestrians, transit (buses sent on from their stops, riders boarding), vehicles (movement, arrivals), then the congestion monitor (every 5 s).

## Layout

```
core/    autoloads (Game, Events) + Grid helpers
sim/     simulation state & systems: SimClock, Simulation, roads/, routing/, city/ (lots, zones, citizens, parking, external connections, flow metric), traffic/ (vehicles, freight, lights, congestion, stress), walking/ (pedestrians), transit/ (bus stops, lines, buses), debug/ (scenarios)
view/    renderers, camera, overlays
tools/   player tools (ToolManager + RoadTool, BulldozeTool, ZoneTool x4, SignalTool, BusLineTool, RouteTool debug inspector); shortcuts in ToolManager.TOOL_SHORTCUTS; tools with variants (road types) implement BuildTool.get_variants/set_variant, and the palette lists them (families in ToolPalette.FAMILIES)
ui/      HUD (top bar, notifications), ToolPalette (bottom-left build palette: tool families, variant sub-menus, hint line), DebugMenu
scenes/  main.tscn (+ sandbox scenes)
benchmarks/  headless perf scripts (run with --script)
tests/   GUT tests: unit/ (pure sim) and integration/ (main scene + synthetic input); files test_*.gd extending GutTest; traffic_checks.gd = shared safety checks (no overlaps, no conflict-zone violations)
data/    Resources (.tres), e.g. data/road_types/ (one file per road type; the build palette lists them all)
addons/gut/  third-party, don't edit
```

## Code style

- Tabs, static typing everywhere (`var x: int`, `:=`, typed returns), `class_name` for reusable classes.
- `##` doc comment under `extends` explaining the class's role; comment the *why*, not the *what*.
- Private members prefixed `_`. Constants `UPPER_SNAKE`. Signals in past tense (`speed_changed`).
- Input: add actions to `project.godot` `[input]` using `physical_keycode` so bindings follow key position on any layout (WASD = ZQSD on AZERTY).
- New sim logic gets unit tests in `tests/unit/`.
